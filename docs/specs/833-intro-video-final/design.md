## 1. コンセプトと流れ

### 一言で

**「実機の画面 → その瞬間の本番ログ」を1枚ずつめくって見せる。**
LINE の実機スクショと、**同じ時刻の** Cloud Logging / Firestore の記録が手元にそろっている（例: 20:13 の豆知識クイズの画面 ↔ 11:13:43Z の `agent_run` の記録）。体験の画面を見せた直後に、その画面の裏でエージェントが何を決めたかの記録を重ねる。この「めくり」を毎回同じ見せ方にすることで、説明の画面を作らなくても次の3点が伝わる。

| 審査基準 | どこで伝わるか |
| --- | --- |
| ① 課題の新規性・解決策の有効性 | S01 親子がパネルを素通り → S03 パネルを撮って送るとすぐ名前がわかる（実機）→ S04 3つの理由 → S05・S06 図鑑・次の水槽へ |
| ② 自律性（管理・制御・可観測性・セキュリティ） | S07 エージェントが8候補を全部作って1問を選ぶ（**実ログ**）→ S09 ヒント＋2択とコードによる差し止め → S10 難易度を決めるが動かせるのは1段・8秒 → S11 駅とツールを選ぶ → S12 ログ・ハッシュ・停止スイッチ・インジェクション試験 |
| ③ 実装品質・拡張性（ツール活用・運用性・費用対効果） | S08 作り置きで 35.6秒→2.8秒・費用は約40分の1 → S11 MCP 84,527→310 トークン → S13 しくみ |

### A・B・元版との違い（採ったもの／捨てたもの）

- 元版から: 冒頭の親子の演出（`Figure` の人と子どもが弾んで走る）、タイトル、ガチャ、探検、仕組みの図、エンディングの2人。
- A から: 数字の出典を画面の隅に小さく出す `Src`、作り置きと「その場で作る」の競争（`Ch3.tsx` の A12）。「3つの問いと答えのカード」の枠組みは**使わない**（説明画面が増え、デモが細切れになるため）。
- B から: `306614_0.jpg` をズームしながら追うヒント場面（`scenesB.tsx` の B6）、ログ・停止・試験のパネル（B7）。「左 LINE／右研究室」の固定2分割は**使わない**。場面ごとに「スマホ1台を大きく」「スマホ＋記録カード」「図だけ」を切り替える。
- 全体: 説明だけの画面は S04（理由3つ・約10秒）と S13（しくみ・約14秒）だけ。それ以外は必ず実機の画面が映っている。

## 2. シーン表

### 2.0 共通ルール

- 画面 1920×1080・30fps。字幕帯（`Subtitle`）が下 約170px を使うので、**主要な内容は y < 900 に収める**。
- 話者 id は `config/voices.json` のとおり **`narrator` / `kawauso` / `jinbei`**（`dr-jinbei` ではない）。
- `speak` は読み上げ用。英字・数字・記号の読みを固定する（下表の「speak」列）。字幕は `text` を出す。
- 尺の見積もりは**既存3本の実測 0.167 秒/字**（`timeline*.json` の発話合計÷字数。依頼の 0.13〜0.15 より遅いので、安全側としてこちらで見積もる）。シーンの前後の間（lead 8f / tail 12f）とセリフ間（pauseAfter 6f）を足し、さらに映像だけの見せ場の `minSec` で伸ばす。
- 数値を画面に出すときは、右下に `Src`（`v2a/common.tsx`）で出典を小さく出す（例: `出典: Cloud Logging 2026-10-08`）。
- 実機スクショの時刻（LINE の「午後8:12」）と、ログの時刻（UTC `11:12:16Z`）は 9 時間差。記録カードには **JST に直した時刻**を「20:12:16 の記録」と出し、画面の時刻と一致することを目で確かめられるようにする。
- 既存音声の流用: `text`・`speak`・話者が完全に同じセリフは、旧 wav を新 id の名前で `public/voice-final/` にコピーしてよい（`generate-voice.ts` はハッシュが一致しないと作り直すので、`manifest.json` に旧エントリの hash/seconds も移す。面倒なら作り直しでよい）。流用候補は表に「流用」と書いた。

## 5. 検証方法

### 5.1 尺

- `timeline-final.json` の `totalFrames / 30` が **178 秒以下**（目標 160〜170）。超えたら 6章の順で削る。
- `npx remotion render src/index.ts IntroVideoFinal out/intro-video-final.mp4 --concurrency=1`（要件10）。書き出し後 `ffprobe` で `duration < 180`、`1920x1080`、音声トラックありを確認。

### 5.2 静止画（シーンごと）

- 各シーンの「最後のセリフの中ほど」と「シーン末尾の 10f 前」を `npx remotion still ... --frame=<n>` で書き出し（または mp4 から `ffmpeg -ss` で抜く）、14シーン×2枚を目で確認する。見る点:
  - 字幕帯と内容が重ならない（y < 900）
  - スマホのスクショが切れていない・セリフの位置にスクロールしている
  - 記録カードの時刻が、スマホの画面の時刻と同じ分になっている（S07 20:13／S09 20:12／S10 20:11／S11 撮影時刻）
  - 各数値の横に `Src` が出ている
- 禁止事項の目視チェック（全フレーム）: mp4 を 2fps で抜いて 1枚のタイルにし、「SSレア」「レア」「イメージ」「これから」「今後」の文字、案内板の写真が無いことを確認する。S05 は gacha の区間を 10fps で抜いて、バッジが1フレームも出ていないことを確認。

### 5.3 音ズレ

- `timeline-final.json` の各セリフの開始フレームで、字幕が出ていることを静止画で確認（Subtitle はタイムライン駆動なので、ずれるのは画面の演出側）。
- 演出の切り替え（めくり・`Ring`・ズーム・候補の点灯・カウントアップ）は**必ず `lineAt`/`lineEnd` からの相対フレーム**で書く（固定フレームを書かない）。音声を作り直しても追従する。
- 書き出した mp4 で、S07 q-2 の開始 ↔ めくり、S09 h-2 の開始 ↔ ジンベエの吹き出しのズーム、S11 s-3 ↔ 棒が 310 に縮む、S08 c-2 ↔ 左の時計が止まる、の4点を `ffmpeg -ss <秒>` の静止画で前後 0.3 秒以内か確かめる。
- 各 wav の末尾に雑音が無いこと（`generate-voice.ts` の末尾除去が効いていること。`--retrim` あり）を、S02・S05・S11・S14 の流用音声を中心に耳で確認。

### 5.4 出典の照合

2章の「数値と出典」に出てくる値を、実装後に1行ずつ出典ファイルと突き合わせる（特に 4章で再取得したもの）。出典が用意できなかった数値は、画面とナレーションの両方から外す（要件5）。

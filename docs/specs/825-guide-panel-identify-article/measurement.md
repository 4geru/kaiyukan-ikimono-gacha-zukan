- 実行: 2026-10-07 / `cd backend && GOOGLE_CLOUD_PROJECT=dummy npx tsx scripts/compare-matching-logic.ts`
- API・Firestore は使わない。243 種は `backend/data/kaiyukan-animals.json`（件数 243、id の重複なし）の並び順
- 現行ロジックは `identifyFish.ts` の `findBestMatchingAnimal` / `confidenceFor` を直接呼ぶ。旧ロジックは初期コミット `d1ae6c44` の `findMatchingAnimal`（和名・学名・英名の双方向包含で `Array.find`）。入力が和名だけなので和名部分のみで比較（結果は実物と同じ）

## 読み取れること・注意

- ハリセンボン: 旧ロジックは配列の前方（idx1）の劣る部分一致を採用。現行は idx103 の完全一致を採用し、並びを変えても同じ
- カサゴ: 現行は「カサゴ」を含む候補のうち長さ比が最大のタカサゴ（0.75、high）。旧ロジックは並び順で最初に当たる種（この並びではユメカサゴ）。どちらも別種で、現行の方が high と表示される分だけ見かけの確からしさは高い
- ツバメウオ: Design 時点の見積り（high の範囲）は誤りで、実測は low（5/7）。再検証記録に結果の記載がなかった点が、これで確認できた
- 抽出名の正誤（Gemini が実際に「カサゴ」と読んだか）はこの計測の対象外。再検証記録の記述の引用にとどめる
- 配列順は JSON ファイルの順。Firestore の取得順と同じである保証はない

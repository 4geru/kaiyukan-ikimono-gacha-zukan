# Requirements — クイズの難易度レベルとヒント付き再挑戦

Issue: [#829](https://github.com/4geru/tweet-bookmark/issues/829)（親: [#779](https://github.com/4geru/tweet-bookmark/issues/779)）

## 目的

クイズを「誰にでも同じ問題を出し、外れたら答えを言う」から、**その人の状況を見て難易度を変え、外れたらヒントで考えさせる**ものにする。審査基準「自律性・エージェントらしさ」の「状況を判断しながら自律的に行動」「適切に管理・制御」「可観測性」に応え、当初要件（779）の「理解度に応じた難易度調整」を実装する。

## 前提（コードで確認済み）

- 難易度の概念は無い。プロンプトは「小学生にも分かる言葉で」の1種類（`quiz.ts` の `buildPrompt`）
- 不正解のときは即座に「正解は〇〇じゃったよ」と答えを返し、次は同じカテゴリで**別の問題**を作る（`planQuizCategory` の `retry`）
- 回答時に `pendingQuiz` を削除し、`quizHistory` には category・question・choices・correctIndex・isCorrect だけを残す（`server.ts` の `handleAnswerQuiz`）
- 新しいカテゴリの出題は ADK エージェント（全部作ってから選ぶ方式、約25〜40秒）。この方式は残す（2026-10-08 ユーザー決定）
- 当初要件（779）: 年齢層で言い回しを変えるが、**事実と正解は年齢層によらず共通**

## ユーザーの決定（2026-10-08）

| 論点 | 決定 |
| --- | --- |
| 難易度の決め方 | エージェントが学習状況を見て理由付きで決め、コードで縛る |
| 難易度の段階 | 5段階（1=幼児向け、3=一般常識、5=お魚博士向け） |
| 難易度の単位 | ユーザー全体で1つ |
| ヒントのタイミング | 不正解のあと。答えを言わずにヒントを出し、同じ問題に再挑戦 |
| ヒントの中身 | 2段階（ジンベエの一言 → 50:50） |

## 受け入れ基準（EARS）

### 難易度

1. system SHALL 難易度を5段階（レベル1〜5）で持ち、ユーザーごとに1つ保存する。初期値はレベル2「みならい研究員」（2026-10-08 ユーザー決定。今のクイズはレベル3相当なので、既存ユーザーも1段やさしい問題から始まる）
2. system SHALL 各レベルを「言葉づかい」「問う事実の深さ」「誤答の近さ」の3つで定義する（2026-10-08 ユーザー指示: 1は幼児向け、3は一般常識のクイズ、5はお魚博士向けの難しいもの）

| レベル | 想定 | 言葉づかい | 問う事実 | 誤答 |
| --- | --- | --- | --- | --- |
| 1 | 幼児 | ひらがな中心・ひとこと程度の短い文 | 見てわかること（色・形・大きさ・どこを泳ぐか） | はっきり違うもの |
| 2 | 小学校低学年 | やさしい言葉・短い文 | 公式の説明にそのまま書いてある基本（すみか・食べもの） | 違いがわかりやすいもの |
| 3 | 一般（一般常識） | 小学生にも分かる言葉（今の水準） | その生きものについて広く知られている一般常識（説明と参考資料で確かめられるもの） | もっともらしいもの |
| 4 | 中高生〜大人 | ふつうの言葉 | 理由・比較・生態のしくみ（なぜ？ どっちが？） | 近いもの |
| 5 | お魚博士 | 専門用語も可（科名・学名など） | 分類・近縁種との違い・細かい数値 | ごく近いもの（近縁種・近い値） |
3. WHEN 新しい問題を出す THEN system SHALL エージェントに学習状況（直近の正誤・連続不正解数・ヒントの使用・現在の難易度）を渡し、次の難易度と理由を決めさせる
4. IF エージェントが決めた難易度が現在から2段以上離れている、またはレベル1〜5の範囲外 THEN system SHALL コードで±1段・範囲内に丸め、丸めたことを記録する
5. IF エージェントが時間内（目安8秒）に難易度を返さない、または失敗した THEN system SHALL 規則（2連続正解で1段上げる・不正解で1段下げる）で決め、規則で決めたことを記録する
6. WHEN クイズを表示する THEN system SHALL 難易度をレベルと呼び名で見せる（例: 「レベル1 ちびっこ」〜「レベル5 お魚博士」。呼び名は Design で決める）
6b. WHEN 難易度が前回から変わった THEN system SHALL キャラクターが一言で変化を告げる（例: 「次はちょっと難しいぞい」）。レベルの表示と両方で伝える
7. system SHALL 難易度レベルで問題の言葉づかいと深さを変える。レベル1では「進化の歴史・海外の小ネタ・類似した仲間・同じ水槽にいる魚・郷土料理」の5カテゴリを新規出題の候補から外す（出し直しでは外さず、言い換えて出す）。当初要件（779）の年齢層対応（年齢入力で言い回しを変える）は本 Issue では実装せず、レベル1〜2がその役割の一部を担う

### ヒント付き再挑戦

8. WHEN ユーザーが1回目に不正解を選ぶ THEN system SHALL 正解を言わず、ジンベエ名誉教授のヒントを添え、**選んだ誤答を消した2択**で同じ問題に再挑戦させる（ヒントの一言と 50:50 を1回にまとめる）
9. WHEN 2択の再挑戦でも不正解だった THEN system SHALL 正解と短い解説を発表し、その問題を終える
10. WHEN 2択の再挑戦で正解した THEN system SHALL 正解として扱い、ヒントを使ったことを記録する
11. system SHALL ヒントの一言を LLM で作り、選択肢を消す処理はコードだけで行う（消すのはユーザーが選んだ誤答）
12. IF LLM のヒントに正解の選択肢の文字列、またはヒントに残っている誤答（2択に残す誤答）の文字列が含まれる、または生成に失敗した THEN system SHALL その一言を使わず、定型のセリフ（例: 「ひとつ消しておいたぞい」）と2択だけで再挑戦させる
13. system SHALL ヒントを出題時に作らず、不正解のときにだけ作る（全部作ってから選ぶ方式の待ち時間を延ばさない）。1段目の生成は数秒以内を目安にする
14. WHEN 正解が出る、または問題を終える THEN system SHALL 次の出題の流れ（今の「不正解の間は同じカテゴリ」「正解したら別のカテゴリ」）につなげる

### 管理・可観測性

15. system SHALL 難易度の決定ごとに「決定前の難易度・決定後の難易度・理由・決めた主体（エージェント／規則）・丸めの有無」を記録する
16. WHEN 問題を終える THEN system SHALL `quizHistory` に難易度・ヒントの使用段階・挑戦回数・最終的な正誤を残す
17. system SHALL 正解（correctIndex）を、問題を終える前に LIFF から読める場所へ書かない（`firestore.rules` の `pendingQuiz` 読み取り禁止を維持）
18. system SHALL 古い問題への回答を今どおり `quizToken` で弾く。再挑戦中の回答も同じ仕組みで検証する。10秒以内の連打・Webhook の再送には返信しない

### 互換性

19. system SHALL 既存の LINE の操作（クイックリプライの「クイズ」、回答の A/B/C）を変えずに使えるようにする
20. IF 既存ユーザーに難易度が保存されていない THEN system SHALL レベル2（初期値）として扱う

## スコープ外

- 年齢層対応（年齢入力フォーム・言い回しの調整）
- 「全部作ってから選ぶ」クイズエージェントの方式変更・高速化
- 案内エージェント（次の一手）全体。本 Issue は難易度とヒントに絞る
- LIFF 図鑑での難易度・ヒント履歴の表示（余力があれば Design で検討）
- デモ動画の撮り直し（別途判断）

## 決定事項（2026-10-08 ユーザー回答）

- 不正解のあとの流れ: 1回目の不正解で「ジンベエのヒント＋選んだ誤答を消した2択」で再挑戦、2回目の不正解で正解を発表（旧・未決論点1の案a）
- 難易度の変化: キャラクターの一言とレベルの表示の両方で伝える（旧・未決論点3）
- ヒントに残っている誤答（2択に残す誤答）の文字列を書いた場合も不合格にする（基準12）
- レベル1では「進化の歴史・海外の小ネタ・類似した仲間・同じ水槽にいる魚・郷土料理」を新規出題の候補から外し、出し直しでは外さず言い換えて出す（基準7）
- 10秒以内の連打・Webhook の再送には返信しない（基準18）
- コーチに規則の案も見せる
- デモ動画では評価スクリプトの判断ログを、字幕で明記して使う

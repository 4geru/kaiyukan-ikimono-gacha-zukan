# Requirements — ハッカソン提出記事: 海遊館いきものガチャ図鑑

Issue: [#822](https://github.com/4geru/tweet-bookmark/issues/822)（親: [#821](https://github.com/4geru/tweet-bookmark/issues/821)）

## 目的

Google Cloud Japan AI Hackathon Vol.5 の提出記事として、「海遊館いきものガチャ図鑑」（LINE Bot × LIFF）が**どんな困りごとを、どんな体験で解決するか**を審査員と一般の読者に伝える。技術の詳細はシリーズの解説記事（#823〜#826）に任せる。

## 前提

- 投稿先は Zenn（`articles/` 配下、`published: false` で作業し、公開はユーザーが判断する）
- プロダクトの仕様は `docs/specs/779-ikimono-gacha-zukan/` とプロジェクトの `CLAUDE.md` が正
- **公式の提出要件（必須項目・タグ・文字数・デモ動画・締切）は未確認**。ハッカソン公式ページで確認してから Design に反映する
- 審査基準は Fable ヒアリング（`docs/2026-09-18-22-40-fable-design-hearing.md`）に書かれた「新規性・有効性」「自律性・エージェントらしさ」「実装品質・拡張性」の 3 つ。これも公式ページで確認する

## 記事の型（Zenn 人気記事の調査から）

過去の Google Cloud 系 AI ハッカソンの提出記事で、いいねの多いもの（120〜143♡）に共通する型に合わせる。

- 冒頭に **TL;DR**（何を作ったか・数字で示す効果・試せるリンク）
- 読者が自分ごとにできる **困りごとの話**から入る（例: 水族館で案内板を読まずに通り過ぎてしまう）
- **使い方を 3 ステップ**程度で、画面のスクショ付きで見せる
- 技術の話は**アーキテクチャ図 1 枚＋要点**にとどめ、詳細は解説記事へリンクする

## 受け入れ基準（EARS）

### 審査基準への対応

1. WHEN 審査員が記事を読む THEN system SHALL 公式の審査基準それぞれに対して、作品のどこが応えているかが分かる（基準ごとの見出しか表で示す）
2. WHEN 「自律性」を説明する THEN system SHALL エージェントが自分で判断している場面（駅の特定、クイズのカテゴリ選び、キャラの掛け合い）を、観察できる証拠（ツール呼び出し・選んだ理由の記録など）とともに示す
3. IF 公式の提出要件に必須項目（タグ・デモ動画・リポジトリ URL など）がある THEN system SHALL すべて満たす

### 内容の正しさ

4. WHEN 機能・数値（243 種、13 カテゴリ、関西 15 館など）を書く THEN system SHALL 現行コード・データと一致させる
5. WHEN 解説記事の数値（トークン数・所要時間など）を引用する THEN system SHALL 解説記事の計測結果と同じ値を使う
6. IF 機能が未実装または一部だけ動く（レアリティ抽選・LIFF 本実装など、`CLAUDE.md` の TODO） THEN system SHALL 動いているように書かない。今後の展望として書き分ける
7. WHEN 海遊館のデータの出どころに触れる THEN system SHALL 非公式の JSON を使った PoC であることを明記する

### 構成・見せ方

8. WHEN 読者が冒頭を読む THEN system SHALL TL;DR だけで「何を作ったか・誰のためか・どう試せるか」が分かる
9. WHEN 全体の構成を図示する THEN system SHALL 段階単位の「ユーザー体験の旅」の図にし、クラス名・メソッド名を書かない
10. WHEN 技術の詳細に触れる THEN system SHALL 要点だけを書き、解説記事（#823 駅すぱあと MCP、#824 クイズエージェント、#825 案内板の識別、#826 キャラの掛け合い）へリンクする
11. IF LINE のトーク画面のスクリーンショットを載せる THEN system SHALL ユーザー名・アイコンなどの個人情報を隠す。案内板の写真は載せない（#825 の決定に合わせる）

### 公開前

12. WHEN 執筆が完了する THEN system SHALL `/article-review` でレビューし、客観的な指摘を反映する
13. IF 記事に秘密情報（アクセスキー・トークン）や非公開 URL が含まれる THEN system SHALL 削除する

## スコープ外

- 解説記事の内容（#823〜#826 で扱う）
- デモ動画の制作（必須と分かった場合は別 Issue にする）
- Zenn への公開操作・応募フォームの送信

## 未決の論点

1. **公式の提出要件と審査基準**: ハッカソン公式ページの URL をユーザーに確認する
2. **試せるリンク**: LINE 公式アカウントの友だち追加 URL / QR コードを載せるか（審査期間中に誰でも使える状態にするか）
3. **リポジトリの公開**: GitHub リポジトリを公開してリンクするか（このモノレポには他プロジェクトも含まれる）
4. **公開順**: 解説記事より先に出すか、解説記事をそろえてから出すか

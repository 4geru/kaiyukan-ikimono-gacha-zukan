# 作り置きの問題データの形式と作問の手順（#831）

2026-10-08 ユーザー決定: **作り置きの問題は Claude で全部作る。作問は Haiku、レビューは Sonnet**。まず5種で試作し、時間・使用量・合格率を測ってから残りを回す。

## 対象
- 生きもの × カテゴリ（13）× レベル（1〜5）。レベル1では `LEVEL_EXCLUDED_CATEGORIES`（`backend/src/quizLevel.ts`）の5カテゴリを作らない → 1種あたり 13×5−5 = **60問**（1マス1問）
- 試作の5種: 48 ジンベエザメ／206 ナンヨウマンタ／209 カクレクマノミ／30 オウサマペンギン／178 コツメカワウソ

## 入力（コードで作る。LLM は使わない）
`backend/scripts/build-quiz-pool-input.ts <animalId...>` が、1種ごとに `backend/data/quiz-pool/input/<animalId>.json` を書く。
- 生きもの: `data/kaiyukan-animals.json` の name・englishName・scientificName・family・classification・mainExhibition・description
- 参考資料: `.cache/wikipedia-extracts.json` の抜粋（無ければ空）
- 実在の仲間: 同じ科（family）の全種名・同じ展示エリア（mainExhibition）の全種名（先頭だけでなく全部）
- レベルの定義: `quizLevel.ts` の `QUIZ_LEVELS`（言葉づかい・問う事実・誤答）と `LEVEL_CATEGORY_NOTES`
- カテゴリの方針: `quiz.ts` の `CATEGORY_BRIEFS`（focus / avoid）と `COMMON_QUIZ_RULES`
- 作るマスの一覧（category × level、除外済み）

## 出力（1行1問の JSONL）
`backend/data/quiz-pool/<animalId>.jsonl`

```json
{"id":"48-生息地-2","animalId":"48","category":"生息地","level":2,
 "question":"…","choices":["…","…","…"],"correctIndex":1,
 "explanation":"正解の根拠を1〜2文（出典の言葉で）",
 "factSource":"official|wikipedia|general|none",
 "groundingNames":["…"],
 "generatedBy":"claude-haiku-4-5","generatedAt":"2026-10-08T…Z",
 "review":{"status":"pending"}}
```

- `id` は `<animalId>-<category>-<level>`（1マス1問）
- `factSource`: 正解の根拠がどこにあるか。`none` はダジャレだけ
- 「類似した仲間」「同じ水槽にいる魚」は、正解・誤答とも入力の実在の仲間の名前だけを使い、使った名前を `groundingNames` に入れる。誤答に入力の仲間（正解になりうる種）を使わない
- 正解・誤答の文字列が重複しない／選択肢は3つ／correctIndex は 0〜2 で、正解の位置は偏らせない

## レビュー（Sonnet）
`review` を次のどれかに書き換える（同じファイルを上書き）。
```json
"review":{"status":"approved|rejected","reviewer":"claude-sonnet-5-5","issues":["…"],"reviewedAt":"…"}
```
- 見る点: 正解が入力の事実（説明・参考資料・仲間の一覧）と矛盾しない／正解が1つに決まる（誤答が正解になりうるものは不合格）／レベルの定義（言葉づかい・事実の深さ・誤答の近さ）に合う／カテゴリの方針に沿う／同じ生きものの他の問題と同じ事実を使い回していない
- 直せば済むものは `issues` に修正案を書いて `rejected`（レビュー担当は問題文を書き換えない）

## 機械的な検査（LLM を使わない）
`backend/scripts/validate-quiz-pool.ts` — 形式（必須項目・選択肢3つ・重複なし・correctIndex の範囲）、マスの欠け・重複、レベル1の除外カテゴリが無いこと、正解位置の偏り、`groundingNames` が入力の仲間に含まれること。

## 記録
`docs/specs/831-quiz-pool/pool-progress.md` に、種ごとの「作問済み／レビュー済み／合格数／不合格数」と、試作の所要時間を追記していく。

## 試作で分かったこと（2026-10-08）と追加ルール
1体の Haiku に5種を続けて書かせたところ、後半の3種（209・30・178）が「〇〇の生息地について？」のような雛形の量産になった（60問中、問題文が15種類しかない）。前半の2種（48・206）も、レベル5で正解の選択肢だけが極端に長く、長さで答えが分かる問題があった。

- **1種につき1体**で作問する（文脈を短く保つ）。他の種のファイルは読まない
- 機械的な検査に次を追加する（validate-quiz-pool.ts）:
  - 1種の60問の問題文がすべて異なる
  - 雛形の禁止: 問題文が「について？」「について（追加）？」で終わるもの、生きものの名前とカテゴリ名だけでできた問題文
  - 選択肢の長さ: 正解の文字数が、誤答の平均の1.6倍を超えない。3つの選択肢の文字数の差は最大でも2倍まで（最長が 8 文字以下の場合は検査を適用しない）
  - 「無関係」「不明」「系統不明」「同一種」など、明らかに選ばれない誤答の禁止語
  - 正解の位置の偏り（今のまま）
- 事実が足りないカテゴリは、入力にある事実だけで問いを作る。資料で確かめられない学術的な言い回し（例: 「独立進化を示す」）を正解にしない

## 第1波のレビューを受けた追加ルール（2026-10-08）
第1波（15種）のレビューで、合格率は 63〜76%。主な不合格の理由は「レベル2の漢字」「同じ事実の使い回し」「ダジャレが言葉遊びになっていない」「根拠のない数値」で、作問とレビューで基準がずれていた。次を正式なルールにする。

1. **漢字**: レベル1は漢字を使わない（ひらがな・カタカナのみ）。レベル2は**小学2年までに習う漢字（学年別漢字配当表の1・2年、計240字）だけ**。validate-quiz-pool.ts で機械的に検査する（問題文・選択肢が対象。explanation は対象外）
2. **使い回しの禁止**: 同じ生きものの60問で、同じ事実を2回以上問わない。レベルを変えて同じ事実を言い換えた問題も使い回しとみなす
3. **ダジャレ**: どのレベルでも言葉遊び（音の重なり・掛け言葉）として成立させる。学名の意味などを問うだけの事実クイズにしない。誤答はオチとして成立しないものにする（誤答も成立するなら不合格）
4. **数値・年号・語源・人名など細かい事実**: 入力資料（説明・参考資料・仲間の一覧）にあるものだけを使う。一般知識で書かない
5. **題材**: 論争的な話題（イルカ漁・捕鯨・アザラシ猟と毛皮など）は使わない。食べない生きものの郷土料理は、仲間の魚の食文化や「食べない」ことの理由を、論争にならない範囲で問う
6. **答えを問題文に出さない**（例: 「ふかひれに使われる部分は？→ひれ」は不可）
7. **選択肢の種類をそろえる**（「魚は？」に哺乳類を混ぜない、区分の体系を混在させない）
8. **カテゴリの主役はその生きもの**: 深度で「水圧のしくみ」、水温で「サンゴの白化」のように、生きものから離れた一般論にしない

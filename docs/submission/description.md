## 対象ユーザー像と課題

水族館が大好きな人（旅行先で水族館を探す、年パスで通う、ダイビングもする）と、水族館へ行く親子が対象です。水槽の横には魚の名前と解説の案内板がありますが、多くの人は読まずに次の水槽へ進みます。子どもならなおさらで、本物の生きものを前にしても名前を知らないまま通り過ぎてしまいます。何度も通っても「見た魚」の記録は残りません。

## ソリューション

LINE の公式アカウント「博士と助教授のひみつ研究室」と、LINE 内で開く図鑑ページ（LIFF）です。インストールは要りません。水槽の**解説パネルを撮って送る**と、Gemini が写真から名前を読み取り、大阪・海遊館の243種と照らし合わせて候補を返します。選ぶと図鑑に登録され、ガチャ演出とキャラクターの反応が届きます。同じ水槽・同じ科の仲間をたどる、13カテゴリの三択クイズ、「彦根駅から1時間で行ける水族館は？」といった駅からの水族館探し（関西15館）もできます。案内役はカワウソ助教授とジンベエ名誉教授の2人で、掛け合いで出題・案内します。

## 特徴

**新規性: 魚ではなく解説パネルを撮る**
1. 名前が書いてあるので、見た目から推測するより取り違えが少ない
2. 撮るために解説を目にするので、読む習慣がつく
3. 図鑑に載った魚を、本物で水槽の中に探す体験につながる

**自律性: エージェントが判断し、コードで縛り、記録する**
- ADK のクイズエージェントは、候補カテゴリすべての完成形を検討し、その生きもの「ならでは」の1問を自分で選びます。駅の探索エージェントは、駅名の曖昧さを文脈で解決し、使うツールを使い分けます。
- 選べるカテゴリやツールの引数はコードで固定し、タイムアウトや失敗時の返事も決めています。検討した全候補と選んだ理由は Firestore に保存します。

**実装品質と費用対効果**
- 駅すぱあと MCP の結果は 84,527 トークンですが、コードで水族館の候補に絞り 310 トークンにして渡します（約270分の1）。案内板の読み取りは推論をオフにして速くし、クイズの出し直しはエージェントを呼びません。
- 鍵は Secret Manager、LINE の署名を検証、LIFF は本人の記録だけ読める Firestore ルールにしています。

**現状の限界**: レア度は抽選しておらず、ガチャ演出はデモ用です。案内板を取り違えることがあります。自動テストはありません。
